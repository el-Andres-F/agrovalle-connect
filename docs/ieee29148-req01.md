# Especificación de requisitos — REQ-01 Registro de productores

**Proyecto:** AgroValle Connect · **Historia fuente:** HU-01 Registro de Productores · **Estándar de referencia:** ISO/IEC/IEEE 29148:2018 · **Estado:** propuesta verificable para la iteración; la regla de municipios debe ser confirmada por el Product Owner.

## 1. Propósito y alcance

Este documento establece los requisitos verificables para registrar productores agrícolas. No reemplaza los criterios BDD; formaliza su comportamiento y relaciona cada obligación con verificación.

## 2. Actores y contexto

- **Actor principal:** administrador autenticado que registra productores desde el panel de gestión.
- **Sistema:** AgroValle Connect, aplicación Spring Boot con API REST, persistencia JPA y PostgreSQL.
- **Fuera de alcance de esta historia:** registro público de administradores y autenticación de productores.

## 3. Requisitos prescriptivos

| ID | Requisito («El sistema deberá…») | Prioridad | Verificación |
|---|---|---|---|
| REQ-HU01-01 | El sistema deberá permitir que un administrador autenticado envíe nombre, ubicación y cédula para crear un productor. | Must | Prueba de integración REST |
| REQ-HU01-02 | El sistema deberá rechazar solicitudes sin nombre, ubicación o cédula con HTTP 400. | Must | Pruebas de límites |
| REQ-HU01-03 | El sistema deberá aceptar cédulas compuestas de 6 a 10 dígitos y rechazar otros formatos con HTTP 400. | Must | Pruebas unitarias y REST |
| REQ-HU01-04 | El sistema deberá impedir que una cédula identificadora se registre más de una vez y responder HTTP 409 ante duplicados. | Must | Prueba REST y restricción UNIQUE |
| REQ-HU01-05 | El sistema deberá guardar el productor y responder HTTP 201 con su identificador y datos no sensibles. | Must | Prueba REST y verificación de persistencia |
| REQ-HU01-06 | El sistema deberá impedir que un usuario no autorizado cree productores. | Must | Prueba REST sin sesión y con sesión de comprador |
| REQ-HU01-07 | El sistema deberá persistir productores en una transacción ACID con clave primaria y campos obligatorios. | Must | Inspección JPA/DDL y prueba de integración |
| REQ-HU01-08 | El sistema deberá validar que la ubicación corresponda a un municipio permitido por el negocio antes de aceptar un productor. | Must, pendiente de decisión | Prueba de aceptación una vez aprobada la lista oficial |

## 4. Decisión pendiente de producto

El término «municipio del Valle del Cauca» requiere acordar si se permiten los 42 municipios del departamento, únicamente zonas atendidas actualmente, o localidades adicionales. No se codifica una lista supuesta. El Product Owner debe aprobar el catálogo y su fuente antes de cerrar REQ-HU01-08.

## 5. Escenarios BDD asociados

- **Registro válido:** Dado un administrador autenticado y datos válidos, cuando envía la solicitud de registro, entonces el sistema crea el productor, lo persiste y responde 201.
- **Cédula mal formada:** Dado un administrador autenticado, cuando envía una cédula fuera del rango de 6–10 dígitos o no numérica, entonces responde 400 y no crea la fila.
- **Cédula duplicada:** Dado que una cédula ya pertenece a un productor, cuando se intenta registrar nuevamente, entonces responde 409 y conserva un solo registro.
- **Sin autorización:** Dado un usuario no administrador, cuando intenta crear un productor, entonces responde 403.
- **Ubicación no permitida:** pendiente hasta aprobar el catálogo geográfico; una vez definido, ubicación no permitida debe responder 400 y no crear la fila.
